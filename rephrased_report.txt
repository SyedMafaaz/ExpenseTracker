CHAPTER 3
System Analysis and Project Overview

3.1 Introduction to the Project

The project undertaken during the internship was the development of a "Smart Expense Tracking Application" - a comprehensive financial management tool designed to help users monitor their income and expenses effectively. The application was built using modern web technologies and deployed using cloud infrastructure and containerization solutions.

The primary motivation behind this project was to address the need for a user-friendly, feature-rich expense tracking solution that combines traditional manual entry with modern automation capabilities. The application enables users to record transactions, visualize spending patterns through interactive charts, and automatically extract data from receipt images using OCR technology.

3.2 Problem Statement

In today's fast-paced lifestyle, individuals often struggle to maintain accurate records of their daily expenses and income. Manual tracking methods are time-consuming, prone to errors, and lack analytical insights. Existing solutions either oversimplify the tracking process or overwhelm users with complex features. There was a need for a balanced solution that offers:

- Easy transaction recording with categorized expenses and income
- Visual analytics to understand spending patterns
- Automated data extraction from physical receipts
- Budget monitoring and financial goal tracking
- Export capabilities for financial reporting

3.3 Proposed Solution

The Smart Expense Tracking Application addresses these challenges by providing:

1. **Interactive Dashboard**: A comprehensive overview of financial status with real-time metrics including total income, total expenses, budget allocation, and remaining balance. Visual charts display spending distribution by category and daily cash flow patterns.

2. **Transaction Management**: A robust system for adding, viewing, and managing transactions with support for multiple expense and income categories. Users can record transactions with details such as amount, category, date, and description.

3. **Receipt Scanner**: An innovative OCR-based feature that allows users to upload receipt images and automatically extract transaction amounts. The system uses Tesseract.js for text recognition and intelligent parsing algorithms to identify financial data.

4. **Data Export**: Functionality to export transaction data in CSV and PDF formats for external analysis and record-keeping.

5. **Responsive Design**: A modern, user-friendly interface that works seamlessly across desktop and mobile devices with dark mode support.

4.3 Component Implementation

**4.3.1 ExpenseContext - State Management**

The ExpenseContext serves as the central state management solution for the application. It utilizes React's Context API combined with the useState and useEffect hooks to manage global application state.

Key Features:
- **State Initialization**: Loads data from localStorage on application startup, ensuring data persistence across sessions
- **Expense Management**: Provides functions for adding, updating, and deleting transactions
- **Budget Tracking**: Maintains user-defined budget with default value of ₹2000
- **Theme Management**: Supports light and dark mode with automatic DOM attribute updates
- **Data Persistence**: Automatically saves state changes to localStorage using useEffect hooks

Implementation Approach:
The context provider wraps the entire application, making state and functions accessible to all components. Each state variable (expenses, budget, theme) is initialized with a lazy initializer function that reads from localStorage. This ensures that user data is preserved even after browser refresh.

The addExpense function generates unique IDs using the UUID library and prepends new transactions to the array. The updateExpense function maps through the array to find and update specific transactions, while deleteExpense filters out transactions by ID.

**4.3.2 Dashboard Component**

The Dashboard component provides a comprehensive financial overview with interactive visualizations.

Key Features:
- **Financial Metrics**: Displays total income, total expenses, budget target, and remaining balance
- **Budget Progress Bar**: Visual indicator showing budget usage percentage with color-coded warnings
- **Category Pie Chart**: Shows expense distribution across different categories using Chart.js
- **Daily Cash Flow Bar Chart**: Displays income vs. expense comparison for each day of the month
- **Real-time Calculations**: Automatically recalculates metrics when transactions are added or modified

Implementation Approach:
The component filters transactions for the current month using date-fns library functions. It separates income and expense transactions, calculates totals, and computes the remaining budget. Chart data is prepared by aggregating expenses by category for the pie chart and grouping transactions by date for the bar chart.

The component uses Chart.js with React-Chartjs-2 wrapper for rendering responsive charts. Chart options are configured for dark mode compatibility with dynamic text colors.

**4.3.3 Expenses Component**

The Expenses component handles transaction management with a form for adding new entries and a table for displaying existing transactions.

Key Features:
- **Transaction Type Toggle**: Switch between expense and income entry modes
- **Dynamic Categories**: Category dropdown changes based on transaction type (8 expense categories, 6 income categories)
- **Form Validation**: Validates amount and date inputs before submission
- **Transaction Table**: Displays all transactions with date, description, category, amount, and delete action
- **Data Export**: Export functionality for CSV and PDF formats
- **Responsive Design**: Table scrolls horizontally on smaller screens

Implementation Approach:
The component maintains form state using useState hook with fields for type, amount, category, date, and description. The handleTypeChange function updates the transaction type and resets the category to the appropriate default. Form submission validates inputs and calls the addExpense function from context.

For CSV export, the component uses Papa Parse to convert transaction data to CSV format and triggers a download. For PDF export, jsPDF creates a formatted document with an auto-generated table containing all transactions.

**4.3.4 Scanner Component**

The Scanner component implements OCR-based receipt scanning functionality.

Key Features:
- **Image Upload**: Drag-and-drop or click-to-upload interface for receipt images
- **Image Preview**: Displays selected image before scanning
- **OCR Processing**: Uses Tesseract.js to extract text from images with progress indication
- **Data Parsing**: Intelligent regex-based parsing to identify transaction amounts
- **Data Editing**: Allows users to modify extracted data before saving
- **Auto-navigation**: Redirects to expenses page after successful save

Implementation Approach:
The component handles image selection using a hidden file input triggered by a styled upload area. When the user initiates scanning, Tesseract.recognize processes the image with English language model. A logger callback updates the progress percentage in real-time.

The parseText function uses regular expressions to identify amounts in the extracted text. It first searches for explicit total indicators (e.g., "Total: ₹123.45"), then falls back to finding all currency-formatted numbers and selecting the largest value as the presumed total.

Users can edit the extracted amount, date, and description before confirming the save. The component then adds the transaction to context and navigates to the expenses page.

5.5 Bug Fixes and Improvements

During development, several issues were identified and resolved:

**Issue 1: Chart Not Updating**
Problem: Charts did not reflect new transactions immediately.
Solution: Implemented proper dependency arrays in useEffect and ensured chart data recalculates on state changes.

**Issue 2: OCR Amount Parsing Inaccuracy**
Problem: Regex failed to extract amounts from certain receipt formats.
Solution: Implemented fallback logic to find all currency-formatted numbers and select the largest value.

**Issue 3: Dark Mode Chart Visibility**
Problem: Chart text was unreadable in dark mode.
Solution: Configured chart options to use CSS variables that adapt to theme changes.

**Issue 4: Mobile Table Overflow**
Problem: Transaction table broke layout on mobile devices.
Solution: Added overflow-x: auto to table container for horizontal scrolling.

**Issue 5: Budget Calculation with Income**
Problem: Remaining balance didn't account for income properly.
Solution: Updated formula to: (budget + totalIncome) - totalSpent

6.4 Challenges Encountered

**Technical Challenges:**

1. **State Management Complexity**
Managing global state across multiple components required careful planning. The Context API solution simplified prop drilling but required understanding of React's rendering behavior to avoid unnecessary re-renders.

2. **OCR Accuracy Limitations**
Tesseract.js performance varied significantly based on image quality, lighting, and receipt format. Implementing robust parsing logic required extensive testing with different receipt types.

3. **Chart Responsiveness**
Ensuring charts resized properly across devices while maintaining readability required careful configuration of Chart.js options and CSS styling.

4. **Docker Optimization**
Reducing the final Docker image size required implementing multi-stage builds and carefully selecting base images (Alpine variants).

**Non-Technical Challenges:**

1. **Time Management**
Balancing feature development with testing and documentation within the internship timeline required effective prioritization and planning.

2. **Learning Curve**
Adapting to new technologies (Tesseract.js, Docker, AWS) required dedicated learning time alongside development work.

3. **Debugging Complex Issues**
Some bugs required deep investigation into library documentation and community forums to resolve.
